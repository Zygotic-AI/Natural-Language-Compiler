## Decision

The release is seven steps, one command each. Nothing else runs in a release.

| # | Step | Command | Who |
| --- | --- | --- | --- |
| 1 | main to release branch | `gh workflow run start-release.yml -f version=vX.Y.Z` | agent |
| 2 | change branch cut from the release branch, merged back, one at a time | `gh pr merge <PR> --merge` | agent |
| 3 | validate | `./release validate` | agent |
| 4 | sign, once, after validate | `./release sign` | owner |
| 5 | release to main | `./release main` | agent |
| 6 | tag main | `./release tag` | agent |
| 7 | artifacts from the tag trigger | `.github/workflows/release.yml` | CI |

1. **Validate fixes, then checks.** In a fresh worktree of the release branch it writes the version (`integrity/nlc-version.json`) and the noop migration, rewrites the release notes from the titles of the PRs merged since the previous tag (step 2 merges with `--merge`, so each merge commit body is the PR title) and checks them (`tools/nlc_release_notes.py --check`), regenerates every derived file, commits, then runs `./nlc gate --profile release`. Green pushes and prints the statement; on an already validated branch it changes nothing and prints the same. Red prints the failing check and pushes nothing.
2. **One signature.** The statement has the six fields the previous release's checker reads and `Tree:`, the git tree of the validated commit with `integrity/checker-digest.sha256.approval.asc` removed. The owner clearsigns it into that file. No agent creates armor.
3. **Sign only a validated head.** `./release sign` refuses unless it runs on `release/vX.Y.Z`, the worktree is clean, HEAD is `origin/release/vX.Y.Z`, validate's writes change no file on HEAD, and `./nlc gate --profile release` passes on HEAD.
4. **Trust root.** The previous release tag is the nearest release tag on the first-parent line: v0.8.0 (pinned by commit), or a tag whose own commit carries a statement its previous tag verifies with a matching Tree. Tags on side commits are never used; a tag on the line that does not verify refuses.
5. **Tree guard.** `Tree` is read only from the statement gpg verifies with the previous release tag's owner keys; armor with bytes outside the clearsigned block refuses. `./release main` pushes only if the release branch tree (armor removed) equals `Tree`. `./release tag` tags only if the `origin/main` tree (armor removed) equals `Tree` and the previous release tag's `tools/check-checker-digest-signature.py`, with that tag's `integrity/owner-keys/`, returns MET for `origin/main`.
6. **Tag equals version.** `release.yml` stops before the build unless the tag is `v` plus the version in `integrity/nlc-version.json`.
7. **Gate and fixture.** Gate: `tools/nouns/nlc_release_tag_gate/nlc_release_tag_gate.py`. Fixture: `tools/assert-tag-digest-signature-required-fails.py`.

## Consequences

- From superseded ADR 0022: decision 1 (`main` holds the tagged version) is `./release tag` naming the tag from `integrity/nlc-version.json` on `main` plus the tag-equals-version step in `release.yml`; decision 5 (notes with real Highlights before release) is the notes check inside validate. Its other decisions (preflight, target preflight, `verify-deep` ordering, version file only after notes, CI re-check at tag) are dropped.
- No per-branch CI, no required check, no release ruleset (the live `release/*` ruleset is removed once, before the #126 change branches merge). A broken change is found at validate.
- `release.yml` and `integrity/owner-keys/` are outside the signed set until issue #135. Until then, a release that changes `integrity/owner-keys/` also needs the gate-set manifest signature of ADR 0052 that `fitness-owner-key-trust` checks; it is the one exception to "one signature per release".
- Crew mandate 5k (a tag deploys to staging, and production only after a manual promote the owner approves) does not apply to NLC releases: `release.yml` publishes the GitHub Release from the tag, and the step 4 signature is the owner's approval.
- Validate rewrites `docs/adoption/RELEASE-vX.Y.Z.md` from the merged PR titles on every run, so hand edits to that file are overwritten, and a merge that is not a PR merge commit (`Merge pull request #N`) is not listed.
- Defects found in a release are handled by ADR 0025 as amended here (root confirmed by the owner on the #126 RCA): an RCA names the level that failed, judges its fix against the area's written target (this record, for releases), and retires at least what the fix adds unless the owner signs an exception. `tools/validate-rca-packet.py` refuses a packet that does not, inside `./release validate`.
- The v0.9.0 tag is verified by the v0.8.0 checker; from v0.9.0 on only this record applies.
